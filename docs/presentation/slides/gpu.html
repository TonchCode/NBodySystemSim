GPU architecture · RTX 4080 SUPER (AD103, Ada, sm_89)

80 small processors that each juggle 48 warps

The chip

  • 80 streaming multiprocessors (SMs)
  • 64 MB L2 cache, shared by all SMs
  • 16 GB GDDR6X, 736 GB/s
  • PCIe 4.0 ×16 to the CPU

One SM

  • 4 partitions, 1 scheduler each
  • 128 FP32 lanes; rsqrt 16 per clock
  • 256 KB of registers
  • 128 KB L1, shared memory carved from it

How it runs

  • warp = 32 threads, one instruction
  • up to 48 warps per SM
  • a waiting warp is swapped for a ready one
  • different paths in a warp run one after another

Two ways to waste it: idle SMs (too little work) and idle lanes (the 32 threads of a warp want different things).

This is the architecture map the lecturer asked for. Three levels: the chip (80 SMs, a big 64 MB L2, 16 GB of VRAM), one SM (4 schedulers, 128 FP32 lanes, registers, L1/shared), and the execution model. The key idea: a warp is 32 threads that execute the same instruction. If they want different things (divergence), the warp runs each path in turn while the other lanes idle. And an SM hides memory latency by keeping many warps resident and switching to a ready one. Last line sets up the rest of the talk: every load-balancing technique fights either idle SMs or idle lanes. Numbers: 80 SMs, 48 warps per SM, 1,536 threads; 40 registers per thread is exactly what lets 6 blocks of 256 fit (100 % occupancy, zero headroom: 41 registers would drop it to 83 %).
