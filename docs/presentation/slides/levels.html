This is the map for the next six slides. Every technique attacks one of these levels. Between SMs: the grid has too few blocks for 80 SMs, or the last wave is half empty (the tail). Between warps: some warps finish early and their SM waits for the slowest. Inside a warp: the lanes of one warp want different tree paths, so they take turns. This turns out to be the big one for the tree. Between devices: the CPU and GPU, and inside the CPU the fast P-cores and slow E-cores. How we measured it: Nsight Compute was blocked for most of the project, so every force kernel has an instrumented twin that writes the SM id, a global timer and a clock per block, plus work counters per warp. From that: idle SMs, tail, SM efficiency, per-warp max/mean, SIMT efficiency. The twin differs from production by −3.4 to +6.2 % in time, so its timelines are used for structure, not for speed.
