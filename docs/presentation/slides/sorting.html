#4 and #5 run the identical kernel; the only difference is which body each thread gets. In #4 a warp's 32 bodies are random, so their walks diverge and the warp runs them one after another. In #5 they are neighbours along the Morton curve, so they mostly open the same nodes, and neighbouring warps share tree nodes in L1. Numbers: best vs best at 1M, θ = 0.5: 71.11 ms → 34.45 ms, 2.06×; 2.01× at 262,144. Hilbert order gives the same as Morton. Active lanes and L1 hit rate are from Nsight Compute. Crossover: the sorted tree (build + traversal) beats the best all-pairs kernel from about 39,700 bodies, at θ = 0.5. What limits #5: not occupancy (flat from 2 to 11 blocks per SM) but L1 capacity: with the full L1 it is 1.51× faster. The profiler later showed why: half the loads miss L1 and saturate L2. Honesty point: Burtscher 2011 says sorting gives about an order of magnitude; we measured 2× on different code and hardware, and we do not claim a contradiction.
