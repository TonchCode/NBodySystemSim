Instruction-level and thread-level parallelism

Two ways to hide a wait, measured

ILP: inside one thread

Independent instructions issue back to back. One interaction is a chain of ~11 dependent steps; unrolling lets several chains overlap.

Unroll 1: −21 % · unroll 16: +5 % · full: +8 %
Full unroll at block 1024: −18 % (instruction cache)

TLP: many warps per SM

When one warp waits, the scheduler issues from another. Needs enough threads: occupancy.

q threads per body (#3): 2.56× at N = 4,096
The tree: flat from 2 to 11 blocks/SM

Register prefetch of the next tile, by resident warps per SM:

2 warps +16.1 % · 4 +10.1 % · 8 +7.7 % · full 0 % → ILP replaces missing TLP

Requirement: ILP and TLP. ILP = parallelism inside one thread. A single interaction is a dependency chain: subtract, square, rsqrt, multiply, accumulate; each step waits for the one before. But two different interactions are independent except for the final add into the accumulator, so unrolling the loop lets the compiler interleave them. Without unroll: 21 % slower. Too much unroll at block 1024: the loop no longer fits the instruction cache, 18 % slower. ILP has a cost. TLP = parallelism across warps. The scheduler hides a wait by switching warps. #3 splits each body's sum over q threads: q times more threads, 2.56× at N = 4,096 where SMs were starving. The dark box is the cleanest experiment: the prefetch helps a lot with 2 warps per SM and not at all at full occupancy. With enough warps, TLP already hides the load; with few warps, ILP has to. That is Volkov's 2010 result, reproduced on our card.
