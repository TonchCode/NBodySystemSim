Requirement: profiling, on RAM. Tool: Nsight Systems with --cuda-memory-usage, which records every allocation and free; our script replays them to get the peak live device memory. VRAM: all-pairs 48 bytes per body (3 MiB at 65,536, 48 MiB at 1M). Tree 212.8 bytes per body in the bench: state 48, per-body tree data 60, per-node 76, CUB sort buffer 12.3, plus 16 bytes of bench-only work counters; production is about 197. So 1M bodies need 213 MiB and 4M need 851 MiB; with about 2 GB already used by the desktop, 70–80 million bodies would fit. Transfers: at 1M, 2 host-to-device and 4 device-to-host copies per run, all outside the time steps. The state never leaves the GPU during a step. Host RAM, peak working set: 122 MiB for all-pairs at 65k, 215 MiB for the tree at 1M, 478 MiB at 4M, so about 120 MiB fixed plus 88 bytes per body. Phase shares at 1M: traversal 98.3 % of the step for #5, 92.5 % for #7. Privacy note if asked why traces are not in the repo: the raw .nsys-rep file records the process environment, so only the text outputs are committed.
