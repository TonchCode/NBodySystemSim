#1: the classic GPU Gems tiling. One thread per body; the block loads 256 positions into shared memory and every thread reuses them. Perfectly equal work per thread, and yet at N = 1,000 there are only 4 blocks, so 76 SMs do nothing. #2: we tried 5 block sizes × 5 unroll factors. The best (block 128, full unroll) is the official baseline for every all-pairs speedup. A model miss we logged: block 64 removes the tail exactly as predicted, but was only 8 % faster, not 20 %, because 4× more barriers and tile loads make each interaction about 12 % more expensive. #3: split one body's sum over q threads (thread s takes every q-th body), then add the q partial sums with __shfl_xor_sync in log2(q) steps, registers only. That is more TLP: 2.4–2.6× where the GPU was starving, nothing at 65,536. Rule we kept: every speedup is against the best-tuned baseline of the same session, never against an untuned one.
